## 2. Lo implementado en esta sesión

### Conversión (quick wins)
- Chips del chat rediseñados por intención de dolor.
- Prompt con **cierre concreto** y **resumen de diagnóstico**.
- `buildLeadContext` enriquecido (usa el resumen del bot o el último intercambio).
- Typo "wrowth partner" corregido; mensaje "Google Maps" reemplazado.

### Privacidad y seguridad
- **Confirmación explícita** antes de abrir WhatsApp (tarjeta Sí/Cancelar).
- **Redacción de PII** (`redactContactInfo`) antes de enviar la conversación al
  proveedor de IA y en el contexto de WhatsApp.
- **PII eliminada del historial de git** (commit del "easter egg" saneado con
  `git filter-repo` + force-push). Residuo documentado en el Anexo C.9 del Design
  Doc de Fase 2.
- Política de privacidad actualizada (Supabase, retención 12/90 días, AARCO).
- Consentimiento del formulario menciona Supabase.

### Fase 2 (persistencia + analítica)
- `POST /api/leads`: validación, CSRF (Origin requerido), rate limit (10/min,
  100/día), hash de sesión con pepper, upsert por sesión, notificación.
- `POST /api/events`: 4 eventos anónimos (`chat_opened`, `diagnosis_completed`,
  `whatsapp_clicked`, `lead_captured`) + `lead_attempt` (fallback del cliente).
- Almacén: Supabase (PostgREST vía `fetch`, sin ORM). `LeadStore` / `EventStore`
  desacoplados.
- Notificación: Gmail (Nodemailer + App Password) primaria; Resend opcional;
  WhatsApp (Meta Cloud API) con plantilla de 3 variables.
- Retención: `supabase/purge.sql` (leads 12 meses, eventos 90 días). **No
  programada** (ver pendientes).

### Calidad
- 263 tests unitarios + 42 e2e, typecheck, lint, build en verde.
- LGTM de `forge-reviewer` y OK de `forge-sentinel`.

## 3. Configuración (nombres, sin valores)

Las variables están en **Vercel → Settings → Environment Variables** (Production)
y en `.env.local` para desarrollo local (git-ignored).

| Variable | Uso |
|---|---|
| `OPENCODE_API_KEY` | Proveedor de IA (server) |
| `CHAT_ENABLED` | Kill switch del chat |
| `LEAD_PERSISTENCE_ENABLED` | Kill switch de leads |
| `CHAT_ANALYTICS_ENABLED` | Kill switch de analítica |
| `LEAD_NOTIFY_ENABLED` | Kill switch del email |
| `LEAD_NOTIFY_WHATSAPP_ENABLED` | Kill switch de WhatsApp |
| `SUPABASE_URL` | `https://<project>.supabase.co` (sin `/rest/v1`) |
| `SUPABASE_SERVICE_ROLE_KEY` | Clave **Secret keys** (`service_role`) |
| `SESSION_PEPPER` | `openssl rand -hex 32` (64 caracteres) |
| `GMAIL_USER` | `digitaldevscolombia@gmail.com` |
| `GMAIL_APP_PASSWORD` | App Password de 16 caracteres |
| `LEAD_NOTIFY_EMAIL` | `digitaldevscolombia@gmail.com` |
| `RESEND_API_KEY` / `RESEND_FROM` | Opcional (dominio verificado) |
| `WHATSAPP_ACCESS_TOKEN` | Meta Cloud API |
| `WHATSAPP_PHONE_NUMBER_ID` | ID del número de negocio |
| `WHATSAPP_NOTIFY_NUMBER` | Número del equipo en E.164 (ej. `573113609710`) |
| `WHATSAPP_TEMPLATE_NAME` | `digitaldevs` (default en código) |

**Nota:** `SUPABASE_URL` debe ser solo `https://<project>.supabase.co`. Si se pega
con `/rest/v1`, el endpoint responde 404.
